# Cookie Missing Security Attributes

## Summary

* A literal `Set-Cookie` header is missing `Secure`, `HttpOnly`, or a valid explicit `SameSite` attribute.
* Set all three protections, choosing the `SameSite` policy appropriate for the application.

## Details

Each attribute addresses a different risk. `Secure` restricts transmission to HTTPS. `HttpOnly`
prevents JavaScript from reading the cookie. `SameSite` controls when the browser sends the cookie
with cross-site requests, reducing exposure to cross-site request forgery.

Setting one attribute does not provide the protections of the others. In particular, `Secure`
alone does not prevent script access to a session cookie. The rule reports partially hardened
headers as well as headers with none of the protections.

The attributes must belong to the same cookie. An attribute on another `Set-Cookie` header does
not protect this cookie, even when both headers are set on the same source line. Cookie names or
values containing words such as `Secure` do not count as attributes.

## Solution

Configure cookie middleware to set the attributes consistently. When emitting a literal header:

```javascript
response.setHeader("Set-Cookie", "session=value; Path=/; Secure; HttpOnly; SameSite=Lax");
```

Use `SameSite=Strict` where the application's navigation and authentication flows permit it.
Use `SameSite=None` only when cross-site delivery is required, and retain `Secure`; browsers
require it for `SameSite=None`. An explicit policy avoids reliance on browser-specific defaults.
`SameSite` is defense in depth, not a replacement for the application's CSRF protections.

## Severity Considerations

This is a best-practice finding because cookie purposes differ. The risk is greater for session
identifiers and authentication cookies. If a non-sensitive cookie must be read by JavaScript,
review and document that need before narrowly suppressing the `HttpOnly` finding.

The rule recognizes common literal header forms, not framework cookie-option objects, computed
header values, or protections added by middleware. A clean scan does not establish that every
response cookie is protected. Confirm the effective headers in integration tests.
