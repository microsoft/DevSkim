# HSTS Missing Required Directives

## Summary

* A literal `Strict-Transport-Security` header is missing a `max-age` of at least one year or `includeSubDomains`.
* Configure both directives and send the header over HTTPS.

## Details

HTTP Strict Transport Security (HSTS) tells a browser to use HTTPS for future connections to a
host, including when a user follows an HTTP link. Browsers accept this policy only over a secure
connection. It does not protect a first visit made over HTTP before the browser knows the policy.

`max-age` controls how long the browser remembers the policy, in seconds. This rule uses one year
(`31536000`) as the minimum deployment baseline; RFC 6797 itself does not mandate that minimum.
`includeSubDomains` extends the policy to subdomains. Both protections must be present in the
same header: a long lifetime alone leaves subdomains outside the policy, and a short lifetime with
`includeSubDomains` still expires too soon.

The check accepts decimal lifetimes at or above the baseline, including quoted decimal values,
and compares directive names without regard to case. An unrelated header or a similar-looking
directive name cannot supply a missing protection.

## Solution

Ensure every affected host and subdomain supports HTTPS with a valid certificate before enabling
a long-lived policy with `includeSubDomains`. Then configure the server or application centrally:

```javascript
response.setHeader("Strict-Transport-Security", "max-age=31536000; includeSubDomains");
```

For Nginx:

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

Verify the effective header on HTTPS responses, including error responses, and check subdomain
compatibility during deployment. Preloading is a separate operational decision, not required by
this rule. Adding the `preload` token alone does not enroll a domain in a browser preload list.

## Severity Considerations

This is a best-practice finding. Short lifetimes can be intentional during a staged rollout, and
`max-age=0` intentionally removes a remembered policy. Review such cases against the deployment
plan before narrowly suppressing the finding.

The rule examines common literal header forms. It does not detect an entirely absent HSTS header,
evaluate runtime expressions, or establish that middleware or proxies deliver the policy over
HTTPS. A clean scan is not a substitute for testing the actual responses.
